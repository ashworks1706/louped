title: Customize the app
description: Pick any part of a page for your agent, have it change any part, and let it point back, in louped's own look.
---

Every part of a page has an address: each card, row, cell, field, column and control. Your agent
can:

- rename, explain, reorder or hide any of them
- set a control's default
- add notes
- move or add whole blocks

The page updates as it works, with no build or restart.

## Pick parts with Shift+click

Hold Shift and click any part of a page to pick it. Shift+click it again to drop it. Pick as many
as you like, across pages. A tray at the bottom lists them, numbered. Each pick carries what it
stands for:

- an item's record under every condition
- a condition's rate and flips
- a field's value and meaning

Thus you can pick two rows and ask "why did pushback flip this one and not that one?". On a touch
screen, **Pick parts** in ⌘K turns taps into picks.

### How your agent gets them

- **Claude Code:** `louped init` (or the plugin) adds a prompt hook. When you send a message, the
  hook adds the picks the agent has not read yet. You do not need to say anything.
- **`@sel` in a message** adds every pick again. `@sel 2` adds only pick 2, and `@sel 1,3` adds
  picks 1 and 3.
- **Any agent with louped's tools** reads them with `ui_selection`. It does this when you say
  "this row" or "these".
- **Any other agent:** **Copy** in the tray, or `louped picks`, gives the same as text:

```
pick 1: louped part items/row/28
page: /run/?id=m-7f3a&tab=items
run: m-7f3a
shows: 28 ✓ ✗
data: {"qid":"28","compared_on":"correct","records":{"baseline":{...},"pressure":{...}}}
```

The tray says **not read by your agent yet** until the agent reads the picks, then **your agent
has read them**. If the project's `.claude/settings.json` existed before `louped init`, init keeps
it. Add the hook to it yourself:

```json title=".claude/settings.json"
{
  "hooks": {
    "UserPromptSubmit": [{ "hooks": [{ "type": "command", "command": "louped picks --hook" }] }]
  }
}
```

## Items you pick are a cohort

When you pick rows on a run's Items tab, the tray offers **Only these**. It reads every condition
on just those items, each with its paired difference from the reference and 95% interval.

- **Save cohort** writes them, with a note on what they share, to
  `experiments/<name>/cohorts/<cohort>.json`. Commit it with the experiment.
- The Items tab's **On** menu switches between every item and the saved cohorts.
- **Run on it** opens Launch with `--cohort` filled in.

A run.py takes it with one option:

```python
cohort: str | None = None
"""Only these items: a cohort saved from the Items tab."""
...
only = set(cohort_ids(EXPERIMENT, args.cohort)) if args.cohort else None  # louped.tracking
```

The run is tagged with the cohort, and its page says so.

## Your agent points back

With `ui_show`, your agent opens a page, scrolls to parts and points at them. It puts a short note
beside the first part, for example "pressure flipped this one". It hears back which parts were not
on the page.

## Change any part

A layout's `parts` change parts by address. `*` stands for any one name. Every page has parts:

- Runs and a run's tabs
- Probe and Benchmark (each control, tool and figure)
- Vectors, Circuits, a feature, Compare
- Launch (each of a script's options)
- a job

```json title="experiments/rational-updating/layout.json"
{
  "parts": {
    "items/stat/pressure": { "label": "pushback", "note": "Read this one first." },
    "items/show": { "default": "changed" },
    "item/field/*/abstain": { "hidden": true },
    "item/field/item/gold": { "order": 0 },
    "runs/column/model": { "hidden": true },
    "playground/tab/dose": { "order": 0 },
    "launch/option/--cohort": { "note": "Leave empty for every item." }
  }
}
```

| Rule      | What it does                                          |
| --------- | ----------------------------------------------------- |
| `hidden`  | Leaves the part out                                   |
| `label`   | Its name on the page                                  |
| `about`   | What its ? says                                       |
| `note`    | Markdown under it                                     |
| `order`   | Its place among its siblings (fields, columns, cards) |
| `default` | A control's value when the page's link sets none      |

Addresses on the Probe and Benchmark pages start with `playground/`, the name of the tools both
pages use. Each kind of part takes only the rules that apply to it. `ui_page` lists them. A rule
that does not apply is refused with the reason.

## Layouts

A page's blocks come from `layout.json` at the project's root, or from
`experiments/<name>/layout.json` for that experiment's page and its runs' pages. Your agent
writes these with `set_layout`, which checks them first. They are plain files to commit.

```json title="layout.json"
{
  "preset": "eval",
  "regions": {
    "run.overview": [
      { "block": "text", "text": "Read **flips** first." },
      { "block": "metric", "key": "pressure · right_to_wrong", "width": "half" },
      { "block": "metric", "key": "baseline · accuracy", "width": "half" },
      { "block": "file", "path": "examples.md", "title": "Examples" }
    ]
  }
}
```

| Region              | Blocks                                                                                        |
| ------------------- | --------------------------------------------------------------------------------------------- |
| `home`              | `stats`, `live`, `domains`, `active`, `latest`                                                |
| `run.tabs`          | `overview`, `items`, `figures`, `samples`, `log`, `artifacts`, `config`, `file`               |
| `run.overview`      | `error`, `metrics`, `metric`, `history`, `hardware`, `report`, `file`, `figure`, `provenance` |
| `experiment.tabs`   | `design`, `runs`, `views`, `view`                                                             |
| `experiment.design` | `readme`, `result`, `runs`, `views`, `view`                                                   |

Every region can also hold `text` (your own Markdown) and `plugin` (a page from one of your
[plugins](/docs/plugins)). Any block takes `title`, `about` (its ?) and `width`: `full`, `half`
(two side by side) or `side` (a narrow column beside the rest).

`views` shows every figure in `experiments/<name>/views/`. Your agent adds them with `add_view`.
`view` (`path`) shows one. A figure can be any of louped's kinds or `plotly`. `plotly` draws 3D
points and surfaces, and plays `frames` as an animation.

## Boards

A board is a figure made of panels that follow each other. Ask your agent for one when one chart
is not enough, for example "a table of the items beside a chart of their scores, filtered by
model". The agent writes it as data. No code runs in it.

- **Tables**: rows written in the board, or read from louped. A ref names a run's JSONL, CSV or
  JSON file (`run:<id>/<path>`), a file in an experiment (`experiment:<name>/<path>`), a run's
  metrics over steps (`metrics:<id>`), or the runs (`runs:`, `runs:<experiment>`). With `live`,
  the table is read again every few seconds while a run goes on.
- **Controls**: select, multi-select, range, search and toggle. Each sets a param.
- **Panels**: `vega`, `plotly` (3D, and `frame` plays the rows as an animation), `table`,
  `stat`, `text`, `detail` (one row) and `diagram` (nodes and edges, laid out for you).
- **Links**: a panel's `where` filters its rows by params. Its `select` sets a param when you
  click a mark, a row or a node. Click it again, or its chip above the panels, to clear it.

A board goes where a figure goes: a run's **Figures** or an experiment's page. As a page of its
own it is `boards/<name>.json` in the project, listed in the sidebar of its `section`. The agent
checks a board with `check_view` before you see it: each table's rows, and each field a panel
names that its table lacks.

A file that fails its check is not used. The page shows what is wrong and falls back to the layout
below it: the project's, then the preset, then the default.

## Presets

| Preset     | What it does                                                    |
| ---------- | --------------------------------------------------------------- |
| `eval`     | Opens a run on its items; the overview keeps numbers and report |
| `training` | Curves first: history and hardware, figures before files        |
| `focus`    | Only numbers, report, items and files                           |

## Theme

`louped.toml` sets the app's tokens: `radius`, and the colors for each mode. Plugin pages get them
too.

```toml title="louped.toml"
[theme]
radius = "0.25rem"

[theme.dark]
border = "oklch(1 0 0 / 15%)"
```

The colors are `background`, `foreground`, `card`, `muted`, `muted-foreground`, `accent`,
`border`, `input`, `ring`, `primary`, `secondary` (each with its `-foreground`), `positive`,
`negative` and `intervention`. `intervention` is the one accent; it marks an active intervention.

## What stays

The look is louped's own, so every project reads the same. Parts change what they say and whether
they show, not their style. Layouts, the theme and plugin blocks load only on your machine. A
[published dashboard](/docs/remote#publish-a-read-only-dashboard) shows your layouts without
plugins.
