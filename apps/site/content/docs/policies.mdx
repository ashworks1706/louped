```
policy = model + interventions + adapters + generation settings
```

In an Inspect eval a policy is the `loupe/` model with model arguments:

```sh
inspect eval task.py --model loupe/Qwen/Qwen2.5-0.5B-Instruct \
  -M interventions='{"kind": "ablate", "vector": "refusal.qwen2.5-0.5b-instruct"}'
```

The intervention kinds:

| Kind     | Does                                       |
| -------- | ------------------------------------------ |
| `steer`  | add a saved direction at a layer, scaled   |
| `ablate` | project a direction out at every layer     |
| `inject` | add the state of given passages at a layer |
| `heads`  | zero or mean-ablate named attention heads  |

The other model arguments:

| Argument      | Does                                                                                                         |
| ------------- | ------------------------------------------------------------------------------------------------------------ |
| `bank`        | load named LoRA adapters beside each other, all inactive                                                     |
| `adapters`    | make this subset of the bank live; their deltas add                                                          |
| `merges`      | add PEFT merges of bank adapters (`linear`, `ties`, `dare_linear`, ...)                                      |
| `phases`      | change the live adapters along one generation: `[{"start": 0, "end": 0.5, "adapters": ["a"]}]`               |
| `diffusion`   | serve a masked diffusion model with its sampler settings                                                     |
| `inject`      | the layer and strength at which passages a RAG task sends are injected, and where (below)                    |
| `attn`        | the attention kernel: `eager`, `sdpa`, `flex_attention` or `file.py:function`                                |
| `batch_size`  | requests generated together (8 on a GPU, 1 on a CPU; 1 reproduces a run bit for bit)                         |
| `revision`    | pin a Hub model to a commit                                                                                  |
| `remote_code` | run the modeling code a Hub repository ships, for an architecture transformers lacks; pin `revision` with it |

Directions live under `<home>/vectors`, adapters under `<home>/adapters`, saved models under
`<home>/models`. `loupe train sft` saves an adapter by name (`export.adapter_as`) or a merged model
(`export.merge_as`), which then runs as `loupe/<name>`.

## Where injected passages go

`inject` adds the passages' state at one layer, which is a layer-entry hook. `at` chooses which forward
passes take it, following the hook points of an engine that retrieves while it generates (piramid's
`RetrievalHook`):

| `at`     | Added to                                         | Mirrors                         |
| -------- | ------------------------------------------------ | ------------------------------- |
| `all`    | every token, prompt and reply (the default)      | retrieval at the layer's entry  |
| `prompt` | the prompt's tokens only                         | retrieval at the sequence start |
| `chunks` | the first generated token, then every `chunk`-th | retrieval at chunk boundaries   |

```sh
inspect eval task.py@rag --model loupe/Qwen/Qwen2.5-0.5B-Instruct \
  -M 'inject={"layer": 12, "alpha": 1.0, "at": "chunks", "chunk": 32}'
```

The same experiment then runs against the engine itself through its OpenAI-compatible endpoint,
so a mechanism found here is checked where it is deployed.
