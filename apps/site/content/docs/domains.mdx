---
title: Research domains
description: What louped studies, on two axes, and the checks that make its numbers trustworthy.
---

louped studies two things about language models: **behavior and alignment**, what models do and
why, and **efficiency and systems**, what it costs to run them. A third group, **instrument
checks**, reproduces known results so the other two can be trusted.

These are louped's default domains: a project files its own experiments under them, or lists
domains of its own in `louped.toml` (below). Each axis is split into domains. A question is an experiment in a project's `experiments/`, named
for the question, whose README names its domain and status (`active`, `parked` or `answered`) in front
matter. The Experiments page groups them the same way. A system you study comes in as a model id,
an OpenAI-compatible endpoint, an agent endpoint or logged model calls; nothing in a domain is tied
to one application.

## Behavior and alignment

| Domain                    | Asks                                                                                       |
| ------------------------- | ------------------------------------------------------------------------------------------ |
| Mechanisms                | Which directions, heads, features and circuits carry a behavior, and what moving them does |
| Sycophancy and honesty    | Whether a model holds a correct answer under pressure and updates on valid evidence        |
| Steering and conditioning | How prompts, vectors, soft prompts, ReFT and LoRA compare at reaching one target           |
| Agent behavior            | Whether agents use tools, ground their answers in tool output and report failure honestly  |

## Efficiency and systems

| Domain                                 | Asks                                                                                |
| -------------------------------------- | ----------------------------------------------------------------------------------- |
| Context and retrieval inside the model | Whether retrieved state can reach a model without its prompt, and at which layer    |
| Inference cost and kernels             | What an attention kernel or a serving choice costs in agreement, latency and memory |
| Small and specialised models           | What adapters, distillation and masked diffusion buy a small model on one job       |

## Instrument checks

| Domain                    | Asks                                                                      |
| ------------------------- | ------------------------------------------------------------------------- |
| Reproducing known results | Whether louped's provider and recipes reach reported numbers within noise |

## Methods every domain uses

The domains share louped's methods rather than owning them: a [policy](/docs/policies) (model,
interventions, adapters, generation settings) that runs the same way everywhere;
[grids](/docs/grid) over conditions and seeds with paired intervals and moved/held verdicts;
training (SFT, DPO, GRPO, ReFT) with an eval's check as the reward; and analysis (logit lens,
patching, probes, attention, SAE features, circuits) on the same changed model.

## Adding a domain

The domains above are louped's defaults. A project lists its own in `louped.toml`, each on one of the
three axes, in the order the Experiments page shows them; listing any replaces the defaults:

```toml
[domains.honesty]
axis = "behavior"
title = "Sycophancy and honesty"

[domains.calibration]
axis = "behavior"
title = "Calibration under feedback"
```

An experiment naming a domain its project does not list is an error that names its folder, not
filed under a default.
