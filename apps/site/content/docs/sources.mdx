`sources/` sits beside `experiments/` and is committed with it. Each paper, doc, deck or notebook
there has a key, which is what a citation names, plus a title and the URL it came from.
`sources/index.json` lists them. louped reads each one page by page so that you and your agent
can search and quote it.

```bash
louped source add paper.pdf --key sharma23
louped source add https://arxiv.org/abs/2310.13548
louped source search "sycophancy pushback"
louped source list
```

| You add                                                 | louped keeps                                                 |
| ------------------------------------------------------- | ------------------------------------------------------------ |
| A PDF, `.pptx`, `.docx`, `.ipynb`, `.md` or `.txt` file | A copy in `sources/`                                         |
| An arXiv page                                           | The paper's PDF and title                                    |
| A shared Google Doc or Slides deck                      | A PDF snapshot, so a quote points at text that cannot change |
| A notebook on GitHub or opened from it in Colab         | The `.ipynb`                                                 |
| A direct link to a file                                 | The file                                                     |

A page is a PDF page, a slide, a notebook cell, or a whole Markdown, text or Word file. A
notebook's page also shows the whole notebook with its saved outputs, as Jupyter does. The page
runs no scripts from the notebook, so math shows as TeX and an interactive chart shows only if the
notebook saved a static copy of it. The
search index lives in louped's state folder and is rebuilt from the files whenever one changes,
so it never needs committing.

A Colab notebook kept in Google Drive needs your sign-in, so download it (File > Download .ipynb)
and add the file instead. louped fetches over https from public addresses only, never from this
machine or its local network.

Your agent searches `sources/` with `search_sources` before it looks anything up on the web,
quotes from `source_page`, and keeps a new paper with `add_source`, which records the URL the
file came from.

## Read, pin and cite

The Sources page (G S) searches every page and lists the sources. Open one to read it: a PDF as
it prints, anything else as its text. Select words on the page and press Pin to keep that
passage, with a note if you like. Pins are kept in `sources/pins.jsonl`, each with its quote,
page and the words either side, so a pin can always be found again.

A pin holds words that are on its page. A paraphrase is refused, by the app and by the agent's
`pin` tool alike, so a citation always points at what the source says.

Cite a page in any Markdown louped shows (an experiment's README, say) as
`[@<key> p<page>]`, for example `[@sharma23 p4]`. It shows as a chip that opens the page, and on
hover shows the source's title and the passages pinned there, or says the key is not a source.

## Check a write-up

`louped check` reads the Markdown under `experiments/` and `reports/`, and the decks and documents
in them (or the files you name). It lists what is not grounded, by file and line:

- A result number (a decimal such as 0.92, a percentage, or a fraction such as 12/40) with no ref
  (`run:<id>`, `run:<id>/<file>`) or citation in its paragraph, list item or table. A table counts
  with the paragraph above it.
- A citation that names no source, no page, or a page with nothing pinned on it.
- A ref that does not resolve.
- A pin whose words are no longer on its page, because the source file changed.

It exits 1 when it finds anything, so it can run in CI. Your agent runs it as `check` before
handing over a write-up, as its `ground-claims` and `write-report` skills say. Whole numbers, such
as counts and years, and anything in `code` are not checked, so write versions and paths as code.
